# VTOFF 설계 조사 — 착용 사진 → 옷 한 벌의 상품 사진을 "극한" 정확도로 (2026-10-06)

목표: 한 장 생성 기준 엄격 판정 95% 이상(색·채도, 무늬·글자, 종류·목선·소매, 없던 것 없음, 겉옷/이너 구분).
조건: 상업 이용 가능 모델·데이터만, 실제 짝 데이터 없음(합성), GB10 한 대(128GB). 현재 v3(klein-4B LoRA) 52%.

근거는 두 갈래 조사(VTOFF 전용 문헌 + 인접 분야). 논문 수치는 각 논문 안에서의 비교로만 의미가 있다
(같은 TryOffDiff 의 VITON-HD FID 가 논문마다 18~28 로 다르게 보고됨).

## 1. 문헌이 말하는 것 — 효과 큰 순서

| 순위 | 기법 | 근거(논문 내 ablation) | 우리 실패와의 관계 |
|---|---|---|---|
| 1 | **본체를 키운다** | 같은 구조에서 SD1.5→SDXL DISTS 25.06→20.90 (2604.08716). DiT/SD3 계열이 SD1.x 대비 FID 약 절반 (TEMU 2505.21062, Voost 2508.04825) | 종류·목선·세부(14) |

| 3 | **마스크 + 구조 텍스트 조건** | TEMU 텍스트 제거 FID 5.74→7.75, 마스크 제거 6.58. 텍스트는 VLM 이 *구조 속성만* 기술(색·질감은 일부러 뺌). 넓힌 마스크가 딱 맞는 마스크보다 낫다(DISTS 20.90 vs 21.30) | 겉옷 추출(9), 종류(14) |

보고된 공통 실패: 색이 밝아짐(사전 분포), 흰/검정 옷 artifact, 작은 로고·글자, 목선·허리선 지어내기, 액세서리를 옷으로 착각,
가려진 부분, 레이어링(거의 다루지 않음), seed 민감도. — 우리 84건 실패와 거의 같다.

라이선스: 전용 VTOFF 모델·주요 데이터(VITON-HD, DressCode, STGarment, Dress-ED, TEMU)는 대부분 비상업. 상업 가능한 것은
fal/virtual-tryoff-lora(Apache LoRA 이지만 본체 klein-9B 가 비상업 → 비교용), Dual-VTOFF(OpenRAIL++, VITON-HD 학습). 우리는
**자체 합성 데이터 + Apache 본체** 노선을 유지한다. 학습 도구 Flow-Factory(Apache)는 FLUX.2-klein·QIE-2511 의 SFT/DPO/GRPO/
DiffusionNFT 를 지원한다.

## 2. 설계안

### 모델 형태
- **본체: Qwen-Image-Edit-2511(20B, Apache)** — 문헌 1순위(체급) + VLM 경로가 "재킷 안의 셔츠" 같은 지시를 이해한다.
  지금 LoRA 학습 시험 중(`unpaired/train_qie.py`, 33 s/step, 59GB). 결과가 좋으면 klein-4B 는 빠른 서비스용 학생(증류)으로.
- **입력(조건) 다섯 가지**
  1. 원본 사진 전체(표시 없음 — 초록 외곽선은 결과로 새어 나왔다)
  2. 대상만 밝은 확대(dim crop) — 지금 방식
  3. **넓힌 대상 마스크** 채널 또는 마스크 이미지(문헌 3순위)
  4. **구조 속성 텍스트**: VLM(Qwen3.8)이 사진에서 읽은 종류·목선·소매 길이·여밈·밑단 모양(색·무늬는 쓰지 않는다 — 픽셀에서 가져와야 함)
  5. (나중) **보이는 픽셀 힌트**: 착용 사진의 대상 부분을 평평한 틀로 역-워핑한 이미지(글자·로고용, 학습 때 일부러 손상시켜 의존 과다 방지)

### 데이터
- 지금의 합성 엔진(상품=정답, 사람 사진=입력) 유지 + 실패 맞춤 **hard negative/추가 쌍**
  - 겉옷 추출: 대상 셔츠 위에 다른 재킷·카디건을 덧입힌 입력(엔진 layer) 비중↑, 이너가 아주 조금만 보이는 쌍↑
  - 액세서리: 착용 사진 위 넥타이·스카프·가방(v4 에 1,344쌍) + 목걸이 조각 추가(Fashionpedia 에 목걸이 분류가 없어 따로 마련)
  - 종류: 같은 색 다른 종류 상품(크루넥↔V넥, 반팔↔긴팔, 캐미솔↔티)을 DPO/NFT 의 negative 로
- **try-on 방향 쌍을 같이 학습**(상품+사람 → 입은 사진; 엔진 결과가 그대로 정답) — 문헌 4순위, 데이터 추가 비용 0
- 색 흔들기는 1단계에만, 정답 색과 어긋난 엔진 쌍은 버린다(v3 의 `--max-palette 6`)
- 비상업·저작권 불명 데이터(Garments2Look, VITON-HD 등)는 쓰지 않는다

### 학습 방식
1. **1단계 SFT**(합성 쌍): rectified flow + 영역 가중 손실(옷·글자·목선 영역↑, 가려진 곳의 무늬는 0 — `--hidden-weights`) +
   timestep 분포를 실패 종류별로 조정 + 가능하면 대응 주의 손실(바닥 합성·장신구 쌍은 정답↔입력 대응을 정확히 안다)
2. **2단계 보상 학습**(DiffusionNFT 또는 Flow-GRPO, Flow-Factory)
   - 합성 쌍: 정답이 있으므로 **정답 대비** ΔE00(옷 마스크), OCR 문자열 일치, DINOv2/DISTS
   - 실제 착용 사진(정답 없음): Qwen3.8 생각 모드 체크리스트(종류·목선·소매·추가물·겉옷 여부, 이진) + "맞는 옷" 검사 + 사진 대비 색
   - 해킹 방지: 보상에 쓰지 않는 사람 판정 세트(지금 84건 + 새 세트)로만 성적을 낸다
3. **3단계** 빠른 모델로 증류(서비스 속도)

### 생성 뒤 결정적 보정(한 장을 정확히 만들기 위한 것, 여러 장 중 고르기 아님)
- 색: 사진 속 보이는 대상 색으로 옮기기(조명·화이트밸런스 추정 후, 밝기는 덜) — `unpaired/colorfix.py` 개선
- 글자: OCR 로 읽은 문자열과 다르면 해당 영역만 다시 그리기 또는 원본 픽셀 워핑

### 입력 조건(서비스 정책)
- 대상이 거의 안 보이는 사진(84건 중 4~5건 — 사람도 모름)은 "더 잘 보이는 사진"을 요청한다. 결과를 고르는 것이 아니라 입력 조건.

## 3. 실험 순서(각 단계 끝에 같은 84건 한 장 기준 엄격 판정)
1. (진행 중) v4 klein — 착용 사진 위 장신구 쌍 효과
2. (진행 중) QIE-2511 LoRA SFT — 500 스텝에서 v4 와 비교, 이기면 3000 까지
3. v5 데이터: 마스크 조건 + VLM 구조 속성 텍스트 + try-on 방향 쌍 + 겉옷 hard negative → 이긴 본체로 SFT
4. 2단계 보상 학습(Flow-Factory): 합성 쌍(정답 대비 보상) → 실제 사진(검증기 보상)
5. 색 보정(조명 보정) · 글자 보정 · 보이는 픽셀 힌트
