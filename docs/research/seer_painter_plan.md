# "보는 모델 + 그리는 모델" 결합 계획 (가칭 Seer–Painter, 2026-10-06)

사용자 아이디어: 상업 라이선스 기준 최고의 시각 사전학습 모델(보는 쪽)과 최고의 확산 생성 모델(그리는 쪽)을 합쳐
"동기화"하고, 우리 과제(착용 사진 → 옷 한 벌 상품 사진)로 미세조정한다.

## 1. 부품 선택

| 역할 | 후보 (상업 가능) | 고르는 법 |
|---|---|---|
| 보는 쪽(Seer) | C-RADIOv4-H(NVIDIA Open Model License), DINOv3 ViT-H+/7B(DINOv3 라이선스, 원문 확인), PE-Spatial-G(Apache), SigLIP 2(Apache) | **S0 탐침**: 우리 판정 자료(v2·v3·FireRed 504장 + 은행 속성)에서 선형 탐침으로 ① 맞는 옷(이너 vs 겉옷) ② 종류·목선·소매 ③ 같은 옷 재식별 ④ 색 구분을 잰다. 위치 특징이 강한 것(RADIO/DINOv3/PE-Spatial) 1개 + 의미가 강한 것(SigLIP 2) 1개 |
| 그리는 쪽(Painter) | Qwen-Image-Edit-2511(20B, Apache; 상업 가능 중 독립 아레나 1위), 빠른 판 FLUX.2-klein-4B(Apache) | 지금 QIE LoRA 500스텝 vs klein v4 를 엄격 판정으로 비교 |
| 보조 | SAM 3(대상 마스크), Qwen3.8-27B(구조 속성 텍스트·채점), BiRefNet(누끼) | – |

**원칙: 보는 모델은 "무엇을·어떤 모양으로", 픽셀 경로(VAE·원본 픽셀)는 "정확히 어떤 색·글자로".**
보는 모델은 색 흔들기 증강으로 학습돼 색을 일부러 덜 구분한다 — 색을 보는 모델에 맡기지 않는다.

## 2. 구조 — 세 군데에서 동기화

```
착용 사진 ─┬─ SAM3/엔진 마스크 → 대상 옷 영역
           ├─ Seer(고정) → 대상 영역 패치 특징 ─→ [어댑터: Perceiver 64토큰] ─┐  (A) 입력 동기화
           ├─ 고주파 지도(윤곽·글자 결) ───────────────────────────────────┤
           ├─ VAE 참조(원본 전체 + 대상 확대) ─────────────────────────────┤
           └─ Qwen3.8 → 구조 속성 텍스트(종류·목선·소매·여밈·밑단; 색 없음) ─┤
                                                                           ▼
                                        Painter(QIE-2511 MMDiT + LoRA) ── 생성 상품 사진
                                          │  (B) 내부 동기화: 중간층 특징 ↔ Seer(정답 상품) 정렬(REPA)
                                          │      + 대응 주의 손실(입력 패치 ↔ 정답 패치, 합성 시 아는 대응)
                                          ▼
                                   (C) 출력 동기화: Seer 공간 거리(옷 마스크 안) + 픽셀 ΔE00 + OCR → 손실/보상
```

- (A) **입력 동기화** = AnyDoor/IP-Adapter 계열. 대상 옷의 "정체성 토큰"을 생성기에 직접 준다 → 겉옷 혼동·종류 바뀜.
- (B) **내부 동기화** = REPA(TEMU-VTOFF 가 VTOFF 에서 효과 확인) + Leffa/CORAL 식 대응 손실 → 형상·글자.
- (C) **출력 동기화** = 보는 모델 기준으로 "같은 옷인가"를 손실·보상으로 → 3단계 강화 학습에서 사용.

## 3. 학습 단계

| 단계 | 내용 | 데이터 | 얼마나(추정) | 통과 기준 |
|---|---|---|---|---|
| **S0 탐침** | 보는 모델 4개 비교(선형 탐침) | 판정 504장 + 은행 1.8만 속성 | 반나절 | 맞는 옷 AUROC ≥0.95, 종류 정확도 비교 |
| **S1 동기화 사전학습** | 생성기·LoRA 고정, **어댑터만** 학습: "이 옷의 특징 토큰(+약한 VAE 힌트)으로 그 옷의 상품 사진을 다시 그려라". 착용 사진이 필요 없는 짝 없는 학습 | 은행 상품 1.8만 + Fashionpedia 옷 조각 + 바닥 사진(정답 = 같은 상품). 특징 토큰은 다른 각도·자르기·가림을 준 사진에서 뽑는다(같은 옷의 다른 보기 → 같은 상품) | klein 으로 먼저 하루, QIE 로 2~3일 | 특징만으로 다시 그린 상품의 종류·무늬 일치(엄격 판정 표본) |
| **S2 과제 미세조정** | LoRA + 어댑터 같이 학습. (A)+(B) 손실, 영역 가중(옷·글자·목선↑, 가려진 곳 무늬 0), try-on 방향 쌍 같이, 겉옷·장신구·종류 hard negative 쌍, 색 흔들기는 앞부분에만 | v5 합성 쌍(마스크·속성 텍스트 포함) | QIE 3000스텝 ≈ 1일 | 84건 한 장 엄격 ≥70% |
| **S3 강화 학습** | DiffusionNFT 또는 Flow-GRPO(Flow-Factory). 보상 = (C): 합성 쌍은 정답 대비(ΔE, OCR, Seer 거리, 종류), 실제 사진은 정답 없이(Qwen3.8 체크리스트, 맞는 옷, 사진 대비 색) | 합성 쌍 + 실제 착용 사진(Fashionpedia·AI Hub K-Fashion·CC0) | 수일 | 300장 시험 세트 엄격 ≥90%, 치명적 ≤3% |
| **S4 증류** | 빠른 학생(klein-4B + 같은 어댑터)로 DMD/일관성 증류 | S3 모델 출력 + 합성 쌍 | 1~2일 | 학생이 선생 −3%p 이내, 장당 ≤15초 |
| **후처리** | 조명 보정 색 옮기기, OCR 확인 후 글자 영역 재생성, 입력 조건(대상이 너무 안 보이면 다시 찍기) | – | – | 최종 ≥95% |

## 4. 더 끌어올릴 아이디어(우선순위 순)

1. **S1 의 "같은 옷 다른 보기" 재구성 학습** — 짝 없는 데이터를 대량으로 쓸 수 있는 유일한 길. 은행(같은 상품 앞·뒷면, 스테이션별 사진),
   바닥 합성, 엔진 결과를 "같은 옷의 다른 보기"로 묶는다.
2. **고해상도 대상 확대** — 대상 영역을 1024 로 잘라 따로 넣는다(작은 글자·로고).
3. **Seer 탐침을 그대로 구조 속성 판별기로** — 종류·목선·소매 판별기를 학습 조건과 채점 둘 다에 쓴다(Qwen3.8 의 흔들림 보완).
4. **다중 Seer** — 위치용(RADIO/DINOv3) + 의미용(SigLIP 2) 토큰을 함께. RADIO 가 이미 여러 스승을 증류한 것이라 하나로 충분할 수도.
5. **보이는 픽셀 힌트 채널** — 착용 사진의 대상 부분을 평평한 틀로 역-워핑해 VAE 참조로 넣는다(학습 때 일부러 손상).
6. **실패 맞춤 timestep 분포** — 형상·종류 오류(고잡음 구간)와 색·글자 오류(저잡음 구간)를 따로 강화.
7. **검증기 다중화** — Seer 탐침 + Qwen3.8 + 픽셀 수치가 모두 통과해야 "정답"으로 셈(보상 해킹 방지; 성적은 보상에 안 쓴 사람 판정으로만).

## 5. 평가 — 이 아이디어가 좋은가

**강점**
- 문헌과 맞는다: VTOFF 최고 성능 모델들은 착용 사진을 별도 특징 흐름으로 강하게 넣고(TEMU: 빼면 FID 5.91→9.11), DINO 정렬을 쓴다.
  우리 v3 실패 중 겉옷 혼동(9)·종류(14)는 정확히 "무엇을 그릴지" 문제라 Seer 가 직접 겨냥한다.
- **S1 이 짝 데이터 부족을 정면으로 푼다**: 같은 옷의 다른 보기만 있으면 되고, 은행·바닥 합성으로 수만 개를 만들 수 있다.
- 부품이 모두 상업 가능(Apache·MIT·NVIDIA Open)이고, 기반 모델을 새로 만들 필요가 없다(어댑터·LoRA 만 학습).

**약점·위험**
- **색과 글자는 Seer 가 해결하지 못한다** — 픽셀 경로·후처리가 따로 필요(설계에 반영). 이 부분을 Seer 에 기대면 실패.
- **QIE 20B 에 어댑터를 붙이는 비용**: 스텝 약 30초, 59GB(+holo4 32GB 여유 필요). S1·S2 각각 1~3일. → 동기화 구조는 **klein-4B 로 먼저 검증**(스텝 5초)하고 이긴 설정만 QIE 로 옮긴다.
- **새 토큰 경로가 기존 지시 이해를 흐릴 위험** — 어댑터 출력 크기를 0 에서 시작(zero-init)하고 S1 에서 생성기는 고정.
- **보상 해킹** — S3 보상과 성적 판정을 분리, 사람 판정 세트 유지.
- 독창성은 중간: 개별 기법은 알려져 있다. 다만 "짝 없는 다른 보기 재구성으로 동기화 → 합성 짝 SFT → 검증형 보상 RL → 증류"를
  상업 라이선스·GB10 한 대 조건에서 VTOFF 에 묶은 조합은 보지 못했다.

**기대(추정, 검증 전)**: S2 까지 70~80%(v3 52% 대비 겉옷·종류·장신구 실패 대부분 해소), S3 + 후처리로 90%대. 95% 는 S3 의 실제 사진
보상과 300장 세트에서의 반복 개선에 달려 있다.

## 6. 바로 할 일
1. S0 탐침 코드(`unpaired/probe_encoders.py`): 판정 504장 + 은행 속성으로 4개 Seer 비교(GPU 짧게, holo4 와 같이 돌 수 있음).
2. S1 데이터: "같은 옷 다른 보기" 묶음 만들기(CPU).
3. klein-4B 에 어댑터(Perceiver 64토큰, zero-init) + REPA 손실 구현 → S1 하루 → S2 v5 로 klein 검증.
4. QIE 500스텝 결과가 klein v4 보다 확실히 좋으면 같은 어댑터를 QIE 로 옮긴다.
