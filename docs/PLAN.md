## 0. Context: 왜 이 문서를 쓰나

- **만들려는 것**
  - 사용자가 텍스트로 입력한 신체 정보와 몸에 붙는 옷(또는 거의 맨몸) 사진 여러 장으로 **체형을 분석**하고, 그 체형에 맞는 **스타일링을 추천**한다.
  - **디지털 옷장**을 연결한다. 내 옷을 찍어 올리면 AI가 옷을 분석하고, **내가 입으면 어떤 핏인지**, 옷장 속 옷을 **어떻게 조합해 입으면 좋을지**를 이미지로 보여준다.
  - 옷마다 **몇 번 입었는지, 언제 어떻게 세탁해야 하는지**도 알아서 관리한다.
- **조건**
  - 개인 프로젝트이고 기한은 없다. 출시나 창업도 생각하고 있다. 사업을 확장하면 중고 커머스와 브랜드 연계 광고까지 간다.
  - 유료 API는 쓰고 싶지 않아서 **로컬 AI를 선호**한다. 폰 자체에서 도는 엣지 AI에도 관심이 있다.
  - 보유 장비는 **NVIDIA DGX Spark 1대**다. 폰은 아직 정하지 않았다. 안드로이드와 아이폰을 모두 지원한다.
- **이 문서의 범위**: 무엇을 만들지(기능), 어떻게 만들지(큰 구조와 AI 구성), 어떤 순서로 만들지(로드맵), 어떻게 돈을 벌지(사업 확장)를 정한다. 세부 구조 설계(폴더 구조, API, DB 스키마, 화면)는 이 기획서를 컨펌한 뒤에 한다.

## 1. 결론: 폰 엣지 AI + DGX Spark 하이브리드

**매일 쓰는 가벼운 AI는 폰 안에서(엣지), 무거운 AI는 집의 DGX Spark에서 돌린다.**
- Spark가 꺼져 있거나 인터넷이 없어도 옷장, 코디 추천, 착용·세탁 관리는 폰 혼자 동작한다.
- 정밀 체형 분석, 가상 착용 이미지, 모델 학습처럼 무거운 일만 Spark가 맡는다.

```
 [스마트폰: FitCheck 앱 (React Native/Expo)]            [집: DGX Spark = FitCheck 서버]
  엣지 AI (오프라인 동작)                                  무거운 AI
  · 촬영 가이드, 옷 누끼, 기본 태깅, 색 추출               · 정밀 태깅, 한국어 스타일링 글, 채팅
  · 옷장 검색, 코디 추천, 착용·세탁 관리      ── Tailscale ──▶ · 3D 체형 분석
  · 결과 보기, 알림                             (HTTPS)        · 가상 착용·옷 복원 이미지 생성
                                                              · DB와 사진 원본 보관, 모델 학습
```

| 고민 | 이 구조의 답 |
|---|---|
| 유료 서비스는 싫다 | API 요금이 없다. 드는 돈은 Spark 전기료뿐이다(최대 약 240W). 원격 접속용 Tailscale은 개인 무료 플랜(최대 6명, 기기 수 무제한)으로 충분하다. |
| 폰에서도 로컬 AI가 되나? | **된다. 다만 가벼운 작업까지다.** 2026년 폰은 소형 비전 모델로 옷 인식, 태깅, 짧은 문장 생성을 할 수 있다. 가상 착용 이미지나 정밀 3D 체형은 아직 무거워서 Spark가 맡는다(7.2). |
| 로컬 모델 성능이 걱정된다 | Spark는 128GB 메모리라 대형 오픈모델도 동시에 돌린다(8장). 폰 모델이 헷갈리는 옷은 Spark의 큰 모델이 다시 본다. 최종 판단은 **Phase 0에서 직접 측정한 뒤** 한다. |
| 사진은 폰이 편하다 | 앱은 폰에서 쓰고, 계산은 폰과 Spark가 나눠 한다. |
| 신체 사진이 불안하다 | 원본 신체 사진은 **내 기기(폰, Spark) 밖으로 나가지 않는다**. |
| 나중에 출시하려면? | 엣지 AI 덕분에 계산 대부분을 사용자 폰이 한다. **출시 후 서버비가 크게 줄어드는 것이 가장 큰 이점이다.** 무거운 작업은 클라우드 GPU로 옮긴다(7.4). |

- **앱 형태: React Native(Expo) 네이티브 앱으로 처음부터 만든다.**
  - 하나의 코드로 안드로이드, iOS, 웹을 모두 지원한다.
  - 개인 단계에서는 **안드로이드 기기로 먼저 테스트**한다. 앱 설치가 무료다.
  - iOS는 베타 단계에서 Apple 개발자 계정(연 $99)으로 빌드한다. Mac이 생기면 더 일찍 해도 된다.
  - 웹 버전은 엣지 AI 없이 Spark에 기대는 보조 화면으로 쓴다.
  - 네이티브를 고른 이유: 엣지 AI, 백그라운드 업로드, 더 나은 카메라 제어가 모두 네이티브에서만 제대로 된다.
- **접속**: 폰에 Tailscale 앱을 켜고, Spark는 Tailscale Serve로 HTTPS를 연다. 같은 Wi-Fi에 있으면 데이터는 집 안에서 직접 오간다.
- **한계와 대응**
  - 폰 성능은 기기마다 다르다. RAM 8GB 이상 최신 폰에서 엣지 AI를 켜고, 구형 폰은 Spark가 대신 처리한다.
  - AI 모델(1~3GB)은 앱에 넣지 않고 필요할 때 내려받는다.
  - Spark는 ARM64 구조라 일부 라이브러리 호환성 문제가 있다. NVIDIA 공식 컨테이너(NGC)와 DGX Spark 공식 플레이북을 출발점으로 쓴다.

## 2. 제품 정의

- **한 줄 정의**: "내 몸을 정확히 아는 AI 스타일리스트 + 알아서 관리해 주는 디지털 옷장"
- **차별점**
  1. **실측 기반 핏 예측**: 내 치수와 옷 실측을 비교해 "어깨선이 4cm 내려오고, 엉덩이를 덮는 기장" 같은 **숫자 핏 리포트**를 만든다. 대부분의 가상 착용은 사이즈를 반영하지 못한다.
  2. **근거가 있는 추천**: 왜 내 체형에 맞는지 근거를 함께 보여준다.
  3. **쓰면서 채워지고, 알아서 관리되는 옷장**: 입은 옷을 찍으면 착용 기록과 옷장 등록이 동시에 된다. 세탁 시기와 방법도 챙겨 준다.
  4. **가진 옷 활용 → 옷장 순환**: 가진 옷 조합을 먼저 추천한다. 안 입는 옷은 중고로 팔고, 빈틈을 채울 옷을 알려준다.
  5. **프라이버시 우선**: 신체 사진은 내 기기에서만 처리한다. 치수만 남기고 원본은 지우는 것이 기본값이다.
- **타깃(가정)**: 한국 20~30대 남녀. 체형 분류, 사이즈 체계, 쇼핑몰 실측 표기(가슴단면 등), 세탁 표시는 한국 기준을 따른다.

### 경쟁·참고 서비스 (2026년 기준)

| 서비스 | 하는 일 | FitCheck와의 차이 |

- **포지셔닝**
  - "사진으로 **실측**한 내 몸 × 내 **옷장** × 옷 **실측 사이즈** × **착용·세탁 기록**"을 한 번에 연결하는 곳은 아직 없다.
  - 여기에 "신체 사진이 서버에 남지 않는다"는 신뢰를 더한다.
  - 이 데이터가 쌓이면 중고 거래와 브랜드 광고에서도 "이 사람에게 맞는 옷"을 알려줄 수 있다(12장).

## 3. 핵심 기능

### F1. 체형 분석 & 스타일링 가이드

- **입력(텍스트)**
  - 키, 몸무게, 나이, 성별
  - 평소 사이즈(상의/하의/신발), 줄자로 잰 치수(선택)
  - 고민(예: "다리가 짧아 보여요", "어깨가 넓어요")
  - 원하는 이미지(예: "키 커 보이게", "단정하게"), 선호/비선호 스타일
  - 자유 문장도 받는다(예: "평소 상의 100, 하의 30 입고 허벅지가 두꺼운 편"). LLM이 구조화된 데이터로 바꾼다.
- **입력(사진)**
  - 정면·측면 사진은 필수, 후면은 선택이다. 팔을 살짝 벌린 A자 자세로 찍는다.
  - 기본 가이드는 **몸에 붙는 운동복**(레깅스, 붙는 반팔 등)이다. 실루엣은 이것으로 충분히 드러난다.
  - 맨몸에 가까운 사진은 정확도 이득이 작은 데 비해 위험은 크다.
    - 개인 단계: 로컬 처리를 전제로 선택 사항으로 허용한다.
    - 출시 버전: 받지 않는 것을 권장한다(10장).
- **촬영 가이드(폰, 엣지 AI)**
  - 화면에 실루엣 가이드를 겹쳐 보여준다.
  - 카메라 높이(허리)와 거리(2~3m)를 안내하고, 셀프 타이머를 지원한다.
  - 전신이 다 나왔는지, 팔 각도는 맞는지 실시간으로 확인한다.
  - 고도화: 제자리에서 한 바퀴 도는 10초 영상을 찍으면 여러 각도를 써서 정확도를 높인다.
- **처리(Spark)**: 사진 품질 검사 → 3D 체형 복원(여러 장 동시 피팅) → 치수 추정(오차 범위 포함) → 체형 분류와 비율 분석 → LLM이 스타일링 지식베이스를 근거로 가이드를 쓴다(9.1).
- **출력: 체형 리포트**
  - **추정 치수**: 어깨너비, 가슴·허리·엉덩이·허벅지 둘레, 팔 길이, 다리 길이(인심), 상하체 비율, 등신
    - 모든 값에 ±오차 범위를 표시한다.
    - 줄자로 잰 값으로 덮어쓸 수 있다.
  - **체형 타입**
    - 여성: 모래시계형 · 삼각형(서양배형) · 역삼각형 · 직사각형 · 사과형
    - 남성: 역삼각형 · 사다리꼴형 · 직사각형 · 삼각형 · 원형
    - 비율 특징: 하이/로우 웨이스트, 어깨 경사(각진/처진), 목 길이, 상하체 볼륨 밸런스
  - **스타일링 원칙**: Do / Don't 3~5개와 그 이유
  - **카테고리별 추천/비추천**: 상의(넥라인, 기장, 핏, 어깨선), 하의(라이즈, 핏, 기장, 밑단), 아우터, 원피스, 신발, 액세서리
  - **사이즈 팁**(예: "상의는 어깨 기준으로 고르세요")과 쇼핑 검색 키워드
  - **체형 실루엣 도식**: 실제 사진이 아닌 일러스트

### F2. 디지털 옷장

- **등록**: 4장의 "옷장 채우기 전략"을 따른다. 한 장에 여러 벌 찍기, 입은 옷 사진으로 자동 등록, 택·영수증 스캔 등이다.
- **자동 처리**
  - 폰에서: 누끼, 색 추출, 기본 태깅
  - Spark에서: 정밀 태깅과 한국어 설명
  - 태깅 항목
    - 카테고리/세부 종류: 무신사식 분류(셔츠, 니트, 슬랙스, 데님 등)
    - 색상(대표색 hex 코드 + 이름), 패턴, 소재 추정, 두께 → 계절
    - 핏(슬림/레귤러/세미오버/오버), 기장, 넥라인, 소매, 여밈, 디테일
    - 격식도(1~5), 스타일 태그(미니멀, 캐주얼, 스트릿, 아메카지, 고프코어 등)
- **사람이 확인**: 태깅 결과는 카드를 넘기며 빠르게 확인하고 고친다. 고친 기록은 모델을 개선하는 데이터가 된다.
- **실측 사이즈(선택)**
  - 상의: 총장, 어깨너비, 가슴단면, 소매길이
  - 하의: 허리단면, 엉덩이단면, 허벅지단면, 밑위, 밑단
  - 쇼핑몰 사이즈표 캡처나 택의 품번으로 자동 입력한다.
  - 실측이 없으면 사이즈 라벨과 카테고리 평균값으로 추정하고 "추정치"라고 표시한다.
- **옷장 화면**
  - 카테고리, 색상, 계절, 착용 빈도, 세탁 상태로 필터링한다.
  - 자연어로 검색한다(예: "검은색 니트", "여름 출근용 바지").
  - 비슷한 옷과 중복 구매는 묶어서 보여준다.

### F3. 핏 예측 & 가상 착용 ("내가 입으면?")

- **숫자 핏 리포트**: 옷 실측과 내 치수를 비교해 부위별 여유량을 계산하고, 소재의 신축성으로 보정한다.
  - 예시: 내 어깨 44cm, 가슴둘레 96cm이고 반팔티 L 실측이 어깨 52, 가슴단면 58, 총장 72일 때
    - 어깨: +8cm → 드롭숄더(어깨선이 양쪽으로 약 4cm 내려옴)
    - 가슴: 58×2 − 96 = +20cm → 세미오버
    - 총장 72cm → 엉덩이를 덮는 기장
  - 체형 도식 위에 어깨선, 기장, 소매 끝이 오는 위치를 그려서 보여준다.
- **가상 착용 이미지(Spark)**: 기준 인물 이미지에 옷을 입힌 사진을 생성한다. 숫자 핏 리포트를 생성 조건으로 넣는다.
  - 기준 인물 ①(기본값): **내 아바타(디지털 마네킹)**. 3D 체형으로 만든, 내 몸매를 가진 모델 이미지다. 얼굴은 빼거나 가릴 수 있다.
  - 기준 인물 ②(선택): 내 전신 사진(평상복)
  - 한 벌만 입히거나, 상의·하의·아우터를 코디 단위로 입힐 수 있다.
- **원칙: 숫자가 기준, 이미지는 참고**: 사이즈를 정확히 반영하는 가상 착용은 2026년 현재 연구 단계다. 그래서 숫자 핏 리포트로 판단하고, 이미지에는 "참고용 AI 일러스트"라고 표시한다.
- **사이즈 비교**: 쇼핑 중인 옷(새 옷, 중고 모두)은 S/M/L 각각의 핏을 비교하고 "평소 선호하는 핏이면 M" 같은 추천을 준다.

### F4. 옷장 코디 추천

- **조건**
  - 날씨: 선택한 지역 기준 기온, 강수, 체감
  - 일정/TPO: 출근, 데이트, 하객, 면접, 여행, 운동
  - 원하는 분위기, 최근 착용 기록, **세탁 상태**
- **추천 방식(하이브리드)**
  1. 규칙으로 후보를 만든다. 상의+하의(+아우터+신발) 조합을 만들고 계절·기온·격식 조건으로 거른다. 세탁이 필요하거나 세탁 중인 옷은 뺀다. 이 단계는 폰에서 돈다.
  2. 후보마다 점수를 매긴다. 기준은 색 조화, 스타일 일관성, **체형 적합도**, 실루엣 밸런스(상하 볼륨), 최근 착용 회피, 내 취향(피드백 학습)이다. 이 단계도 폰에서 돈다.
  3. LLM 스타일리스트가 상위 후보 중 3개를 고르고 **이유와 연출 팁**을 붙인다(예: 앞자락만 넣어 입기, 소매 롤업, 톤온톤). 폰의 소형 모델이 짧은 설명을 쓰고, Spark가 연결되면 큰 모델이 더 좋은 설명을 쓴다.
- **시각화**
  - 기본: 옷 누끼 이미지를 배치한 **플랫레이 콜라주**. 폰에서 바로 나온다.
  - 선택: **아바타 착용 이미지**. Spark에서 생성한다.
- **피드백**: 👍/👎와 이유 태그(색 조합이 별로, 너무 격식 있음 등), "오늘 이거 입었어요" 기록을 다음 추천에 반영한다.

### F5. 옷 관리: 착용 횟수 · 세탁 · 보관 (자동)

- **착용 기록 자동화**: 손으로 적지 않게 만든다.
  1. 오늘의 코디에서 "이거 입었어요"를 한 번 누른다.
  2. 거울 셀카(OOTD) 한 장을 찍으면 AI가 옷장 속 어떤 옷인지 알아보고 자동으로 기록한다. 옷장에 없는 옷이면 새 옷으로 등록한다(4장).
  3. 아무것도 안 하면 저녁에 "오늘 이 옷 입었나요?" 알림이 오고, 예상 코디를 보여준다.
- **세탁 정보 자동 수집**
  - 케어 라벨(세탁 표시) 사진에서 세탁 기호를 인식한다: 물세탁 온도, 손세탁, 드라이클리닝, 표백, 건조, 다림질.
  - 라벨이 없으면 소재와 종류로 추정하고 "추정"이라고 표시한다.
- **세탁 주기 관리**
  - 옷마다 "마지막 세탁 후 착용 횟수"를 센다.
  - 기본 주기(아래 예시)를 날씨와 활동으로 보정한다. 덥고 습한 날이나 운동한 날은 앞당긴다.
  - 주기가 되면 "세탁 필요" 상태로 바꾼다.

  | 종류 | 기본 세탁 주기(예시, 사용자가 조정) |
  |---|---|
  | 속옷·양말·운동복 | 매번 |
  | 티셔츠·셔츠·블라우스 | 1~2회 |
  | 니트·스웨터 | 3~5회 |
  | 슬랙스·치마 | 3~5회 |
  | 청바지 | 5~10회 |
  | 코트·패딩 | 시즌당 1~2회(드라이클리닝) |

- **세탁 묶음 추천**
  - "세탁 필요" 옷을 세탁 방식과 색상별로 묶는다. 예: "오늘 세탁기: 어두운 옷 4벌, 30도 울코스"
  - 드라이클리닝 맡길 옷 목록도 따로 보여준다.
- **코디 추천과 연동**: 세탁이 필요하거나 세탁 중인 옷은 추천에서 빼거나 표시한다. 추천받은 코디를 오늘 실제로 입을 수 있어야 한다.
- **보관·계절 관리**
  - 환절기 알림(예: "니트 정리 시즌: 세탁 후 개어서 보관, 방충제")을 보낸다.
  - 오래 안 입은 옷은 알려주고 중고 판매를 제안한다(12장).
- **옷의 수명과 가치**: 1회 착용당 비용(가격 ÷ 착용 횟수)을 보여준다. 보풀이나 변색을 기록해 교체 시기를 알린다.
- **나중(v3)**: LG ThinQ나 삼성 SmartThings 세탁기에 세탁 코스를 바로 보낸다.

## 4. 옷장 채우기 전략 (가장 큰 진입장벽 해결)

**원칙: "전부 찍고 시작"이 아니라 "쓰면서 채워지는 옷장".** 사람들은 옷의 20% 정도를 80%의 날에 입는다. 자주 입는 옷부터 자연스럽게 등록되면 충분하다.

| # | 방법 | 설명 | 커버 범위 | 단계 |
|---|---|---|---|---|
| ① | 기본템 체크리스트 | "흰 반팔티, 연청 데님, 검정 슬랙스…" 목록에서 색만 골라 체크한다. 사진 없이 가상 아이템이 생기고, 나중에 실제 사진으로 바뀐다. **1분 만에 첫 코디 추천을 받는다.** | 기본템 | MVP |
| ② | 한 장에 여러 벌 | 침대나 바닥에 4~8벌을 펼쳐 한 장 찍으면 옷마다 자동으로 분리한다. 옷이 화면에 안정되면 자동 촬영하고, 결과는 카드를 넘기며 확인한다. | 전체 | MVP |
| ③ | **입으면서 채우기(OOTD)** | 거울 셀카를 찍으면 입은 옷을 인식한다. 옷장에 없는 옷이면 AI가 옷만 떼어 상품 사진처럼 복원(virtual try-off)해 카드를 만든다. **착용 기록도 동시에 된다(F5).** | 자주 입는 옷, 오프라인 구매 | v1 |
| ④ | 택·라벨·품번 스캔 | 가격표 택의 품번이나 바코드, 브랜드 라벨을 찍으면 공식 상품 이미지와 실측 사이즈표를 찾아 깔끔한 카드를 만든다. | 오프라인 구매(브랜드 매장) | v1 |
| ⑤ | 영수증 인식 | 종이나 전자 영수증에서 브랜드, 품명, 사이즈, 가격을 읽는다. | 오프라인 구매 | v1 |
| ⑥ | 온라인 주문내역 | 주문 캡처나 주문 확인 메일에서 상품 정보와 사이즈표를 가져온다. | 온라인 구매 | v1 |
| ⑦ | 쇼핑 직후 모드 | 새 옷을 샀을 때 "30초 등록"을 알린다. 택이 붙어 있을 때 찍으면 가장 정확하다. | 새로 산 옷 | v1 |
| ⑧ | 옷장 정리 모드 | 환절기 정리를 하면서 한 벌씩 "보관/판매/기부"로 분류한다. 분류가 곧 등록이 되고, 판매 수익이 동기가 된다(12장). | 전체 | v2 |
| ⑨ | 옷장 스캔 영상 | 옷장 행거를 쭉 훑는 영상에서 옷을 하나씩 감지해 "초안 카드"(색, 종류만)를 만든다. 입을 때 보완한다. | 걸린 옷 | v2 |
| ⑩ | 게임화 | 옷장 완성도(%)를 보여주고, "15벌 등록하면 체형 맞춤 코디 해금" 같은 목표를 준다. | — | MVP |

- **오프라인 구매 커버**: ③ 입는 순간 등록, ④ 택/품번, ⑤ 영수증, ⑦ 쇼핑 직후 알림의 네 겹으로 막는다.
- **완벽함보다 속도**
  - 초안 카드(색, 종류만)로도 추천에 쓴다.
  - 정보가 부족한 옷은 "입을 때 한 장만 찍어 주세요"로 조금씩 보완한다.
- **장기(사업)**: 세탁 수거 서비스나 중고 위탁 업체와 제휴하면, 그 업체가 찍는 사진으로 자동 등록할 수 있다.

## 6. 사용자 흐름

1. **첫날(약 10분)**: 기본 정보 입력 → 기본템 체크리스트(1분) → 첫 코디 추천 → 가이드를 따라 신체 사진 촬영 → 체형 리포트
2. **첫 주**: "한 장에 여러 벌"로 자주 입는 옷을 등록한다. 매일 OOTD를 찍으면 옷장이 저절로 채워진다.
3. **매일**: 아침 알림 → 오늘의 코디 3개(세탁 상태 반영) → 콜라주 보기 또는 착용 이미지 생성 → OOTD 한 장(착용 기록 + 새 옷 등록)
4. **주말**: "세탁 필요" 알림 → 세탁 묶음 안내 → 세탁 완료 체크
5. **쇼핑할 때**: 상품 링크, 캡처, 택 → 핏 예측과 옷장 매칭 → 구매하면 바로 옷장에 추가
6. **환절기**: 옷장 정리 모드 → 보관 안내 → 안 입는 옷 판매글 자동 작성

## 7. 시스템 구성

### 7.1 개인 단계 (지금)

- **폰 앱(React Native/Expo)**
  - 카메라 촬영, 엣지 AI(7.2), 로컬 DB(옷장, 착용·세탁 기록)
  - 백그라운드 업로드와 동기화, 푸시 알림
  - 엣지 AI 네이티브 모듈을 쓰려면 Expo 개발 빌드가 필요하다(Expo Go로는 안 된다).
- **Spark(서버)**
  - **API 서버**: Python FastAPI
  - **작업 큐 + 워커**: 처음에는 PostgreSQL 작업 테이블로 단순하게 만든다.
  - **AI 서빙**: vLLM(VLM), ComfyUI 또는 diffusers(이미지), PyTorch(체형, 누끼)
  - **저장소**: PostgreSQL과 pgvector. 사진은 로컬 파일시스템에 두고, 나중에 S3 호환 저장소로 바꿀 수 있게 만든다.
  - **배포**: Docker Compose. NVIDIA NGC 이미지를 기반으로 한다.
- **동기화 원칙**
  - 폰이 먼저 저장하고(오프라인 우선), 연결되면 Spark와 맞춘다.
  - 원본 사진과 정밀 결과는 Spark가 보관한다.
- **날씨**: 기상청 단기예보 API(무료)를 쓰고, 사용자가 지역(시/구)을 고른다. GPS 위치를 수집하면 위치정보법상 신고 의무가 생기므로 쓰지 않는다.

### 7.2 폰(엣지)과 Spark의 역할 분담

| 작업 | 폰(엣지) | Spark(또는 출시 후 클라우드) | 결정 |
|---|---|---|---|
| 촬영 가이드(자세 인식) | ✅ MediaPipe / Apple Vision | — | 폰 |
| 옷 누끼 | ✅ iOS 피사체 분리, Android ML Kit, 경량 누끼 모델 | 고품질 재처리 | 폰 우선 |
| 색 추출, 콜라주 | ✅ | — | 폰 |
| 옷 기본 태깅(정해진 분류) | ✅ 소형 비전 모델, 또는 Spark에서 학습한 경량 분류기 | 대형 VLM 정밀 태깅과 한국어 설명 | 폰 우선, 애매하면 Spark |
| 옷 검색, 유사·중복 찾기 | ✅ 경량 임베딩 + 폰 안 검색 | — | 폰 |
| 코디 추천(규칙 + 점수) | ✅ 계산량이 작다 | — | 폰 |
| 코디 설명 문장 | △ 소형 LLM으로 짧은 설명 | 대형 LLM으로 풍부한 설명 | 혼합 |
| 착용·세탁 관리 | ✅ | — | 폰 |
| 입은 옷 인식(OOTD) | ✅ 옷 분리 + 옷장과 비교 | 새 옷의 상품 사진 복원(try-off) | 혼합 |
| 세탁 라벨·택·영수증 읽기 | ✅ 기기 내 OCR과 소형 VLM | 어려운 경우 재처리 | 폰 우선 |
| 체형 측정 | △ 2D 실루엣 방식의 대략치 | ✅ 3D 체형 피팅(정밀) | Spark |
| 가상 착용 이미지 | △ 연구 수준(Mobile-VTON: 폰 NPU에서 1장 약 80초) | ✅ FASHN VTON / Qwen-Image-Edit | Spark |
| 스타일리스트 채팅 | △ 간단한 질문 | ✅ 복잡한 대화와 도구 사용 | 혼합 |
| 모델 학습(미세조정) | ❌ | ✅ | Spark |

- **"Spark에서 학습 → 폰에 배포" 루프**
  - Spark의 대형 VLM이 태깅한 결과와 AI Hub K-Fashion 데이터(9.6)로 폰용 경량 분류기를 학습한다(지식 증류).
  - 학습한 분류기를 폰에 내려보낸다.
  - 쓸수록 폰 모델이 내 옷장에 맞게 좋아진다.
- **기기 등급**: 앱이 기기 성능을 확인해 엣지 AI 사용 범위를 정한다.
  - 상급(RAM 8GB 이상): 소형 VLM까지 폰에서 돌린다.
  - 중급: 누끼와 분류기만 돌린다.
  - 하급: Spark가 대신 처리한다.

### 7.3 AI는 "작업 단위 Provider"로 만든다

- **작업 목록**: `옷 태깅`, `누끼/분할`, `옷 인식(재식별)`, `체형 추정`, `착용 이미지`, `옷 복원(try-off)`, `스타일링 글`, `임베딩`, `채팅`
- **실행 위치 선택**: 작업마다 `edge`(폰), `local`(Spark), `cloud` 구현을 두고 기기 등급과 설정에 따라 고른다. 결과 형식(JSON 스키마)은 모두 같다.
- **데이터 등급 가드**: 신체 사진과 치수는 `edge`와 `local`에서만 처리한다. 외부 전송은 코드 수준에서 막는다.
- **섀도 비교**: 같은 샘플을 여러 실행 위치에서 함께 돌려 품질과 비용을 비교한다.
- **모델 레지스트리**: 모델마다 라이선스와 허용 용도를 기록하고, 비상업 모델이 제품 코드에 섞이지 않게 자동으로 검사한다.

### 7.4 출시 단계 (나중)

- Tailscale 구조로는 출시할 수 없다. 모든 사용자가 내 사설망에 들어와야 하기 때문이다.
- 서버 중심부(API, DB, 저장소)를 **국내 리전 클라우드**로 옮긴다.
- Spark는 클라우드에서 **작업을 가져가 처리하는 워커**가 된다. 밖으로 나가는 연결만 쓰므로 포트를 열지 않는다.
- 사용자가 늘면 같은 워커 이미지를 클라우드 GPU에서 돌린다.
- **엣지 AI의 사업적 가치**: 태깅, 추천, 옷 관리 같은 매일 쓰는 계산을 사용자 폰이 하므로, 서버비는 착용 이미지와 정밀 체형 분석에만 든다.

## 8. AI 모델 구성

### 8.1 DGX Spark로 어디까지 되나

- **사양**: GB10 Grace Blackwell, 128GB 통합 메모리(대역폭 273GB/s), 20코어 ARM CPU, CUDA 13
- **메모리**: 아래 서버 모델을 전부 동시에 올려도 약 60~70GB라서 여유가 있다.
- **속도**: 공개 벤치마크 기준이고 일부는 추정이다. Phase 0에서 직접 잰다.

  | 작업 | 속도 |
  |---|---|
  | VLM Qwen3.6-35B-A3B (NVFP4) | 약 100 토큰/초 (단일 요청) |
  | 참고: 70B급 dense 모델 | 약 2.7 토큰/초 → 느리다. **MoE 모델을 쓴다** |
  | FLUX급 이미지 생성 | 장당 15~30초 |
  | Qwen-Image-Edit + 고속(Lightning) LoRA | 장당 15~40초 (추정) |
  | FASHN VTON v1.5 | H100에서 약 5초 → Spark는 수십 초 예상 |

- **ARM64 주의사항**
  - flash-attn이 동작하지 않는다. PyTorch 기본 attention(SDPA)을 쓴다.
  - xformers와 detectron2는 직접 빌드해야 한다.
  - onnxruntime-gpu는 ARM 버전이 없다.
  - SAM 3D Body는 detectron2가 필요하므로 별도 컨테이너로 분리한다.
  - NVIDIA 공식 DGX Spark 플레이북(vLLM, ComfyUI, Tailscale, VLM·FLUX 미세조정)을 출발점으로 쓴다.

## 9. 핵심 로직 설계

### 9.1 체형 측정

1. 사진마다 SAM 3D Body가 3D 체형(MHR)의 초기값을 추정한다.
2. **모든 사진에 체형 하나를 동시에 맞춘다**(피팅).
   - 체형은 하나로 고정하고, 자세와 카메라는 사진마다 따로 둔다.
   - 입력한 키로 크기를 고정한다.
   - 이 단계가 필요한 이유: 사진 한 장만 쓰면 SAM 3D Body가 평균 체형 쪽으로 끌려가는 경향이 있다.
3. 한국인 인체치수 통계(사이즈코리아)를 기준 분포로 써서 튀는 값을 보정한다.
4. clad-body로 표준 치수(ISO 8559-1)를 추출한다. 줄자로 잰 값이 있으면 그 값을 우선한다.
5. 비교 기준선으로 2D 실루엣 방식(정면 너비 + 측면 두께 → 타원 둘레)도 구현한다. 이 방식은 폰의 대략치 계산에도 쓴다.

- **기대 정확도**: 연구에서 사진 기반 둘레 오차는 평균 약 1~3.4cm다. 설문만으로 추정하면 약 3~4cm다.
  - 목표: 가슴·허리·엉덩이 평균 오차 3cm 이하
- **체형 분류**: 규칙 기반이다(예: 어깨-엉덩이 차이, 허리-엉덩이 비율). 결과를 설명할 수 있고, 같은 입력이면 항상 같은 결과가 나온다.
- **확인 필요**: 사이즈코리아 원자료의 상업 이용 조건은 사이즈코리아 측에 문의해야 한다.

### 9.2 핏 예측

- **부위별 여유량** = 옷 치수 − 신체 치수(+신축성 보정). 여유량 구간으로 핏 라벨을 붙인다.
- 예시 초기값(반팔티 가슴 여유량). 카테고리마다 따로 두고, AI Hub 의류 통합 데이터와 실제 착용 피드백으로 보정한다.

  | 0~5cm | 5~10cm | 10~16cm | 16~24cm | 24cm~ |
  |---|---|---|---|---|
  | 타이트 | 슬림 | 레귤러 | 세미오버 | 오버 |

- **착지점**: 기장, 소매 끝, 밑단이 몸의 어디에 오는지 계산한다. 3D 체형의 신체 랜드마크(허리선, 골반, 엉덩이, 손목, 발목) 높이와 비교한다.
- **사이즈 인식 가상 착용**: 연구가 막 나오고 있다(FitVTON 2026.6, Google FIT 데이터셋 2026.4). v2에서 이 방식으로 LoRA 학습을 시도한다.

### 9.3 코디 점수

- **총점** = w1·색 조화 + w2·스타일 일관성 + w3·체형 적합도 + w4·실루엣 밸런스 + w5·신선도(최근 안 입음) + w6·개인 취향
- **사전 조건**: 세탁이 필요하거나 세탁 중인 옷은 제외한다.
- **색 조화**: CIELAB 색공간을 기준으로 한다(무채색 베이스 + 포인트 1~2색, 톤온톤/톤인톤, 보색). 퍼스널 컬러와의 적합도도 반영한다.
- **개인 취향**: 피드백이 쌓이면 가중치를 학습한다.

### 9.4 입은 옷 인식(OOTD) & 옷 상태 관리

- **옷 재식별**
  1. OOTD 사진에서 옷을 부위별(상의, 하의, 아우터, 신발)로 분리한다.
  2. 분리한 옷마다 임베딩을 만들어 옷장 속 옷과 비교한다.
  3. 결과에 따라 처리한다.
     - 유사도가 높으면: 착용 기록에 추가한다.
     - 애매하면: 후보 2~3개를 보여주고 한 번 탭으로 확인받는다.
     - 없으면: 새 옷 후보로 올리고, 상품 사진처럼 복원(try-off)한다. 복원 이미지에는 "AI 복원 이미지"라고 표시하고, 실제 사진으로 바꿀 수 있게 한다.
  4. 얼굴은 인식하지 않는다. 얼굴 부분은 저장 전에 잘라내거나 가린다.
- **옷 상태**: 깨끗함 → 착용 N회 → 세탁 필요 → 세탁 중 → 깨끗함
  - 세탁 주기는 옷 종류, 소재, 케어 라벨로 정한 기본값에 날씨와 활동 보정을 더한다.
  - 사용자가 "아직 괜찮아요"를 누르면 그 옷의 주기를 늘린다(학습).
- **세탁 묶음**: 세탁 방식(물세탁 온도, 울 코스, 손세탁, 드라이)과 색 계열(흰색, 밝은색, 어두운색)이 같은 옷끼리 묶어 한 번에 돌릴 목록을 만든다.

### 9.5 스타일링 지식베이스

- 체형별 규칙, 색 이론, TPO 드레스코드, 세탁 기호 해석을 **사람이 검수한 문서**로 만든다.
  - 예: 역삼각형 → 상의는 V넥·래글런, 하의는 와이드·밝은 색
- LLM은 이 문서를 근거로 답한다(RAG). 그럴듯하지만 틀린 조언을 줄이기 위해서다. 리포트에는 근거가 된 규칙도 함께 보여준다.

| 의류 가상착용 3D 이미지 | 성별·연령별 신체 + 의류 착용 3D | 아바타·가상 착용 연구 |

- **이용 조건**
  - AI 학습용으로만 쓸 수 있고, 학습한 결과물(모델)은 자유롭게 활용할 수 있다.
  - 원본 데이터는 재배포할 수 없고, 해외로 가져가려면 별도 합의가 필요하다.
  - 데이터셋마다 세부 조건이 있으니 신청할 때 확인한다.

### 9.7 생성 이미지 품질 관리

- **자동 검사**: 기준에 못 미치면 자동으로 다시 생성하거나 콜라주로 대체한다.
  - 옷 재현도: 원본 옷과의 유사도(FashionSigLIP, LPIPS)
  - 체형 유지: 실루엣 겹침, 관절 위치 변화
  - VLM 심사: 손이나 옷 형태가 어색한지
- 먼저 저해상도 미리보기를 빠르게 보여주고, 마음에 들면 고화질로 생성한다.
- 같은 조합은 캐시해서 다시 쓴다.
- 모든 생성 이미지에 "AI 생성" 표시를 넣는다(10장).

## 10. 개인정보 · 안전 원칙

- **개인 사용 단계**
  - 신체 사진과 OOTD 사진은 폰과 Spark에서만 처리한다. 외부 전송은 코드 수준에서 막는다.
  - 치수를 추출한 뒤 원본 신체 사진을 자동 삭제하는 것이 기본값이다. 보관은 선택이고, 보관하면 암호화한다.
  - 가상 착용은 아바타를 기본으로 한다.
- **출시 단계에서 추가로 필요한 것**
  - **나이 제한**
    - 신체 사진 기능은 **만 19세 이상**만 쓸 수 있게 한다. 아청법에서 19세 미만은 아동·청소년이다.
    - 만 14세 미만은 법정대리인 동의가 필요하므로 가입을 막는다.
  - **촬영 기준**: 몸에 붙는 운동복 사진만 받는다. 속옷이나 맨몸 사진은 받지 않는다.
  - **개인정보보호법**
    - 신체 사진·치수를 수집할 때 **별도 동의**를 받고, 보관 기간과 파기 규정을 둔다.
    - 해외 API를 쓰면 **국외 이전을 고지하고 동의**를 받는다(제28조의8). Claude API에는 한국 리전이 없다(미국/글로벌).
    - 스타일링용 체형 정보는 개인 식별 목적이 아니면 생체인식정보가 아니다. 다만 얼굴로 본인 확인을 하면 해당될 수 있어서 **얼굴 인식은 쓰지 않는다**.
    - 몸무게·체지방은 건강 관련 정보로 보고 신중히 다룬다.
  - **AI 기본법(2026.1.22 시행, 제31조)**
    - 생성형 AI를 쓴다는 사실을 사용자에게 미리 고지한다.
    - 생성물에는 AI 생성 표시(워터마크나 메타데이터)를 넣는다.
    - 실제와 구분이 어려운 인물 이미지에는 눈에 보이는 표시를 한다.
    - 과태료는 최대 3천만 원이고 1년 이상 유예된다. 그래도 처음부터 표시를 넣는다.
  - **악용(딥페이크) 방지**: 2024년 10월부터 성적 허위영상물은 소지·시청도 처벌 대상이다.
    - 가상 착용의 기준 인물은 본인 사진이나 본인 아바타로만 제한한다.
    - 속옷·수영복 가상 착용은 막는다.
    - 입력과 출력 모두 NSFW 필터를 건다.
    - 약관으로 타인 사진 업로드를 금지한다.
  - **커머스·광고 관련(12장)**
    - 자체 중고 마켓을 열면 통신판매중개업 신고와 전자상거래법상 중개자 의무를 지킨다.
    - 광고·제휴 추천에는 "광고"라고 표시하고 일반 추천과 구분한다(표시광고법, 추천·보증 심사지침).
    - 맞춤형 광고는 별도 동의를 받는다. 광고주에게 개인 데이터를 넘기지 않는다.
  - 사용자 데이터를 모델 학습에 쓰려면 별도로 옵트인을 받는다.

## 12. 비용 · 수익 · 사업 확장

### 12.1 비용

- **개인 단계**: 전기료 정도다.
- **출시 단계**
  - 엣지 AI 덕분에 매일 쓰는 기능(태깅, 추천, 옷 관리)의 서버비는 거의 0이다.
  - 서버비는 착용 이미지와 정밀 체형 분석에 든다. 클라우드로 넘기면 착용 이미지 장당 약 $0.05~0.13이다.
  - 그래서 콜라주는 무료로 무제한 제공하고, 착용 이미지는 횟수를 제한한다.

### 12.2 핵심 자산

- 사용자의 **체형(치수)**, **옷장**(보유 옷, 실측, 착용 빈도, 상태), **취향** 데이터가 핵심 자산이다.
- 다른 커머스는 이 데이터를 갖지 못한다. 그래서 FitCheck만 "**이 사람에게 맞고, 이 사람 옷장과 어울리는 옷**"을 알려줄 수 있다.

### 12.3 중고 커머스 (옷장 순환)

- **파는 쪽**
  - 오래 안 입은 옷을 감지한다(예: 6개월 미착용, 체형이 바뀌어 안 맞는 옷).
  - "판매할까요?" 제안과 함께, 이미 있는 사진·속성·실측·착용 횟수로 **판매글을 자동으로 쓴다**.
  - 시세를 기준으로 가격을 제안하고, 원탭으로 등록한다.
- **사는 쪽**
  - 중고 매물마다 실측이 붙어 있으니 **"이 중고 옷, 내 몸에 맞을까?" 핏 예측**이 된다.
  - 내 옷장과의 코디 가능 수와 가상 착용도 보여준다.
  - 중고 패션의 가장 큰 문제인 "사이즈 실패"를 줄인다.
- **단계**
  1. 판매글 초안을 만들어 기존 플랫폼(번개장터, 당근, 후루츠패밀리 등)에 공유한다. 법적 부담이 없다.
  2. 위탁·수거형 중고 업체와 제휴한다. 수수료를 나누고, 업체가 찍은 사진으로 옷장을 자동 등록한다.
  3. 자체 마켓을 연다. 통신판매중개업 신고, 안전결제, 분쟁 처리가 필요하다.
- **수익**: 거래 수수료, 제휴 수수료, 프리미엄 노출

### 12.4 브랜드 온라인숍 연계 광고

- **형태: "내 몸에 입혀보는 광고"**
  - 브랜드 자사몰 상품을 내 아바타에 가상 착용하고, 내 치수 기준 사이즈를 추천하고, 내 옷장과의 코디 예시를 보여준다.
  - 그다음 자사몰로 연결한다.
- **자연스러운 노출 위치**: 빈틈 분석과 쇼핑 도우미 흐름에 들어간다. 예: "이 슬랙스 하나면 새 코디 9개, 내 치수엔 M"
- **브랜드가 얻는 가치**
  - 사이즈 실패로 인한 반품이 줄어든다.
  - 체형과 취향에 맞는 사람에게만 노출된다.
  - 브랜드는 상품 피드(이미지 + 실측 사이즈표)만 주면 된다.
- **과금 단계**: CPS(판매당 수수료, 제휴 링크) → CPC/CPM 광고 → 브랜드용 사이즈 추천 위젯(B2B), 익명 집계 리포트
- **개인정보**
  - 광고주에게 개인 데이터를 넘기지 않는다.
  - 매칭은 FitCheck 안(가능하면 폰 안)에서만 하고, 브랜드는 익명 집계 성과만 받는다.
  - 맞춤형 광고는 별도 동의를 받는다.
- **신뢰**
  - 광고·제휴 추천은 "광고"로 표시한다.
  - 사용자에게 맞지 않는 상품은 광고비를 받아도 추천하지 않는다. 신뢰가 곧 자산이다.

### 12.5 순환 루프 (플라이휠)

안 입는 옷 감지 → 중고 판매(수익이 포인트로 쌓임) → 빈틈을 채우는 옷 추천(중고 또는 브랜드) → 구매하면 옷장 자동 업데이트 → 데이터가 쌓여 추천이 더 정확해짐 → 다시 처음으로

### 12.6 그 밖의 수익

- **프리미엄 구독**: 착용 이미지 확대, 고화질, 진단 리포트(퍼스널 컬러, 골격), 채팅
- **장기**: 세탁 수거·보관 서비스 제휴, 쇼핑몰용 사이즈 추천 API
- **신뢰 포인트**: "원본 신체 사진을 서버에 남기지 않는 앱"

| 폰 기기 편차(성능, RAM, 앱 용량) | 기기 등급별 기능. 모델은 필요할 때 내려받기. 약한 기기는 Spark나 클라우드로 대체 |
| 라이선스 오염 | 모델 레지스트리를 자동으로 검사하고, 비상업 모델은 실험 폴더에서만 쓴다. LoRA 학습 데이터의 출처를 기록한다. |
| 로컬 모델 품질 부족 | Phase 0 벤치마크로 먼저 확인한다. 모델은 교체할 수 있게 만든다. 미세조정하고, 필요한 기능만 부분적으로 클라우드를 쓴다. |
| Spark 운영(속도·ARM64·가용성) | 우선순위 대기열, 무거운 작업은 밤사이 일괄 처리. 컨테이너 버전을 고정한다. 폰은 오프라인으로도 동작한다. |
| 광고가 신뢰를 깎음 | 광고 표시를 명확히 하고 일반 추천과 분리한다. 체형에 맞지 않는 광고는 걸러낸다. |
| 중고 마켓 운영 부담 | 판매글 생성과 제휴부터 시작하고, 자체 마켓은 규모가 생긴 뒤에 연다. |
| 개인정보·악용 | 10장의 원칙을 따른다. |

## 14. 평가 방법

| 대상 | 지표 | 방법 |
|---|---|---|
| 체형 치수 | 부위별 평균 오차, % ±2cm/±4cm 이내, 반복 측정 일관성 | 한 사람이 ISO 8559-1 방식으로 줄자 실측을 두 번 해서 비교한다(본인 + 동의한 지인). 성별·체격별로 나눠 본다. |
| 옷 태깅 | 속성별 정확도, 색상 오차(ΔE), 스키마 준수율 | 내 옷 300~500벌에 정답 라벨을 달고, K-Fashion 데이터도 쓴다. 폰과 Spark, 클라우드를 같은 세트로 비교한다. |
| 옷장 등록 속도 | 20벌 등록 소요 시간, 등록 경로별 비율 | 앱 로그 |
| OOTD 옷 인식 | 정확도, 재현율, 원탭 수정 비율 | 한 달 치 OOTD 사진에 정답을 달아 비교 |
| 세탁 관리 | 알림 수용률, "아직 괜찮아요" 비율 | 앱 로그. 주기 학습이 잘 되는지 확인 |
| 핏 리포트 | 실제 착용감 일치율 | 실제로 입어 보고 "리포트대로다"인지 체크한다. |
| 착용 이미지 | 옷 재현도, 체형 유지, 자연스러움(1~5점) | 자동 점수 + VLM 심사 + 사람 A/B 비교 |
| 코디 추천 | 👍 비율, 실제 착용률, 다시 뽑기 횟수, 다양성 | 앱 안의 피드백 기록 |
| 사업(Phase 4) | 판매글 → 실제 판매 전환, 광고 클릭 → 구매 전환, 사이즈 추천 이용 시 반품률 | 제휴사 데이터(익명 집계) |

## 15. 컨펌이 필요한 사항

1. 핵심 기능 F1~F5의 범위와 우선순위가 맞는지
2. 옷장 채우기 전략: MVP는 ①②⑩, v1에 OOTD 자동 등록과 택·영수증·주문내역을 넣는 순서가 맞는지
3. "폰 엣지 AI + DGX Spark" 하이브리드 구조와 React Native(Expo) 앱(안드로이드 먼저 테스트)으로 갈지
4. 신체 사진 기준: 개인 단계는 맨몸 사진도 선택 허용, 출시 버전은 몸에 붙는 운동복만 받을지
5. 타깃: 한국 20~30대 남녀 모두로 시작할지
6. Phase 1(MVP) 범위: 단품 가상 착용까지 넣을지
7. 사업 확장 순서: 중고 커머스와 브랜드 광고 중 무엇을 먼저 할지(제안: 판매글 자동 작성 → 제휴 링크 → 입혀보는 광고)
